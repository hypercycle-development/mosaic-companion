# Support and Help

> **DRAFT FOR APPROVAL — NOT YET ADOPTED**

MosAIc Companion is pre-1.0 open-source software. The community will try to help, but the project does not yet offer guaranteed response times, availability, or commercial support unless a separate written agreement says otherwise.

## Choose the right channel

| Need | Channel | Public? |
| --- | --- | --- |
| Reproducible software defect | [GitHub Issues](https://github.com/hypercycle-development/mosaic-companion/issues/new/choose) | Yes |
| Usage or design question | [GitHub Issues](https://github.com/hypercycle-development/mosaic-companion/issues/new/choose) | Yes |
| Feature or integration proposal | Feature, integration, or RFC issue form | Yes |
| Security vulnerability | [Private vulnerability report](https://github.com/hypercycle-development/mosaic-companion/security/advisories/new) | No |
| Conduct or harassment concern | conduct@hyperpg.site | No |


## Before asking for help

Please search existing issues, then include:

- MosAIc version or commit;
- operating system and architecture;
- installation method;
- the shortest steps that reproduce the problem;
- expected and actual behavior;
- relevant logs with secrets and personal information removed; and
- whether the issue involves a WASM tool, MCP server, renderer add-on, wallet, payment flow, or other extension.

Never post API keys, wallet secrets, recovery phrases, tokens, credentials, private user data, or unredacted production logs.

## Response times

MosAIc Companion is currently maintained by a very small team. We do not publish response-time targets, because we would rather set targets when we can meet them than publish numbers we cannot. Expect responses to be best-effort and sometimes slow. Growing the project to the point where it can state service objectives and meet them is a goal, not a present commitment.

Security reports go through GitHub private vulnerability reporting and are prioritized over ordinary issue and pull-request traffic; see [SECURITY.md](SECURITY.md). Maintainers may also prioritize data-loss, compatibility, accessibility, and release-blocking work.

## What maintainers can support

Maintainers can usually help with reproducible behavior in supported releases, documented development workflows, core APIs, and accepted extension interfaces. They may be unable to diagnose proprietary systems, unshared code, unsupported releases, modified builds, third-party service outages, or integrations that require access to private data.

## Company adopters

Companies building on MosAIc should designate a technical contact, reproduce issues against an unmodified supported build when possible, contribute fixes or test evidence upstream, and avoid presenting the community support channel as a contractual service desk. A future partner program may offer structured onboarding and escalation after its terms are approved.
