# Phase 4 test fixtures

`test-signing-key.json` was generated by `generate-test-signing-key.cjs`
(a genuine one-off, offline, manually-run script — same procedure §6.7 of
the architecture doc describes for the real key, just clearly test-scoped).

**This is not, and must never become, the production `mosaic-addons` signing
key.** It exists purely so `electron/addons/signing.ts` and the Phase 4
installer's verify path have something real to sign fixtures with in dev/CI.
The actual production key does not exist yet — it is generated by a
maintainer by hand in Phase 6, under the full custody procedure in §6.7, and
is never derived from or related to this one.

`electron/addons/signing.ts`'s `TRUSTED_PUBLISHER_KEYS` pins the *public*
half of this key as its one placeholder entry (`introducedAt`/`retiredAt`
mark it clearly as a dev/test key, not "keyId 1 of production rotation").
The private key here is used only by test scripts to sign a local test
`addon-registry.json` fixture — never committed as a GitHub Actions secret
anywhere, never used to sign anything that ships to a real user.
